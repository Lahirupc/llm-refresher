# Chunking
Fixed chunking is bad. Use semantic chunking. Chucking affects quality.
1. Chunk size (sweet spot 200-1000 chars)
2. Chunk overlap (10-20% overlap preserves context)
3. Split boundaries (fixed/recursive/semantic - best)
4. Content type - each content type needs different chunking strategy (e.g. code, tables, legal, mark down, etc.)

## Chunking Strategies
1. Fixed-size chunking - never use in production
2. Recursive chunking - good for general purpose (80% RAG systems use this)
3. Semantic chunking (split when the sentence embedding similarity drops) - best for domain specific knowledge

## Traditional Chunking vs Late Chunking

Traditional chunking 
    - split based on the document structure (e.g. paragraphs, sentences, etc.)
Late chunking 
    - split based on the semantic similarity of the sentences (e.g. chunk 5 embedding includes full document context)
    - improves accuracy by 10%-12%
    - used for utting edge cases
